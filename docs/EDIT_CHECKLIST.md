> 정본 규칙은 `docs\STYLE_GUIDE.md`. 이 파일은 그 요약 + 이 프로젝트에서 확정되는 실전 기준이다.
> 애매하면 "허용"으로 남기지 말고 푼다 — 논문 프로젝트에서 남긴 예외는 전부 사용자에게 재지적당했다.

## 1. 간결 — 한 내용 한 문장

- 한 문장에 사실 하나. 수치 뒤에 "~하며, ~는 뜻이다"로 풀이를 잇대지 않는다. 풀이가 필요하면 수치를 풀이 안에 녹인다("약 45%(전월 대비) 상승한다").
- 앞 문장이 부정·한계를 말했으면 다음 문장은 "A가 아니라" 없이 긍정만.
- 겹말 금지(국내외 모두, 뒤 이후로도, 대부분~뿐, 추정하는~추정되는).
- 문단 첫머리 예고문과 맺음문이 같은 말이면 하나를 지운다. 라벨 문장("첫째는 가치이다") 금지.
- 동격·요약의 "즉" 금지. 주장 선행·근거 후행("~기 때문이다"). 예고와 내용 일치.

## 2. 괄호 — 산문에서는 통계값도 서술로 푼다

- 허용: 내주 인용, 영문 병기(첫 등장), 절·표·그림·식 참조, 기간·주차, 단위 환산쌍.
- 금지(전부 서술로): 통계 보고값((MAE=1,700)·(n=60)), 값+출처, 용어 명명, 파라미터 스펙, 문장급 설명, 나열. 표·표 주석 안에서만 허용. 괄호 겹침 절대 금지.

## 3. 직역투 — 영어 골격 탐지

- 공간 은유(~아래의, ~위에서), 명사 사슬·명명(식별의 원천, 해석의 범위, 간명한 사양), 어미·조사(~에서의, ~으로의, ~됨을 보여준다, 시사적이다), 의인화("모형은 ~를 주장한다").
- 판정·수정 순서: KCI 정착 여부 확인 → ① 삭제 ② 서술 해체 ③ 정착어 대체.

## 4. 긁어 부스럼·AI투 — 굳이 밝힐 필요 없는 것은 쓰지 않는다

- 주석·본문에 계산 과정·자료 사정·점검 보고("전 원점에서 ~가 성립하였다")·내부 근거 언급("CABIS 내부 산출물과 일치")을 쓰지 않는다. 판정: **"이걸 빼면 독자가 값을 잘못 읽는가?"**
- 예고 문장("~는 3.2절에서 확인한다", "두 가지 한계가 있다. 첫째"), 되풀이 요약("따라서 …이다"), 가르치듯 한 풀이, 연결 수사("네 결과는 하나로 모인다")를 쓰지 않는다. 핵심 결론 문장의 'A가 아니라 B'만 허용.
- 삭제한 방어 논리는 `wiki\presentation-defense.md`로 옮긴다.

## 5. 용어 — 정착 학술 용어는 유지, 조어는 금지

- STYLE_GUIDE 용어 절을 따른다. 새 용어 판단은 KCI 용례 검색. 확정된 폐기 용어는 `tools\style_rules_local.py`에 즉시 등록.

## 6-1. 표 (정본은 STYLE_GUIDE "표·그림")

- 열은 "무엇을 / 어떻게 / 결과". 행 이름은 일반화된 명사. 연속 구간 `~`, 별개 설정 `/`. 각 행에 기준값 병기. 대안이 여럿이면 보수적인 하나만, 나머지는 주에. 주는 개조식. 캡션은 개조식 명사구. 표의 세부 수치를 본문에서 반복하지 않는다.
- 결과표의 모형 이름은 README와 같게(가격만 ridge / 기상 ridge / 기상 HGB / 여름특화 HGB / 계절편차 ridge / Chronos-2 제로샷 / MSTL+AutoARIMA / MSTL+AutoETS).
