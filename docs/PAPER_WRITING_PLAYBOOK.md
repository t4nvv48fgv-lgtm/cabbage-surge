## 1. 절대 규칙 (학술 무결성) — 사용자가 요청해도 완화되지 않음

### 인용
- 존재하지 않는 문헌을 인용하지 않는다. 저자·연도·제목·저널·DOI·페이지를 기억으로 재구성하지 않는다.
- 인용은 (a) `references.bib`에 있는 키 (b) 사용자가 제공·확인한 출처만. 불확실하면 본문에 넣지 말고 `[CITATION NEEDED: 무엇에 대한 근거]`.
- 본문 인용 ↔ 참고문헌 목록 완전 일치. 등록은 했어도 **원문을 읽지 않은 문헌(status: unread)은 존재 인용만, 수치 인용 금지**.
- 인용 오남용 점검: 인용 문장 ↔ 초록 대조. 실제 사례 — "겨울배추 저장·출하 실태" 근거로 단 문헌이 실제로는 여름배추 저장온도 실험이었음 → 문장 수정.
- 출처 없는 수치는 정본에서 제거한다(실제 사례: "약 90일 저온저장 물리적 한계" 2곳 삭제, 재도입 시 1차 자료 인용 필수).

### 데이터·결과
- 수치·통계·표·그림을 지어내지 않는다. 값은 `data/` 또는 재현 가능한 스크립트 산출물에서만. 없으면 `[VALUE NEEDED]`.
- 본문·표·그림의 모든 수치는 **어느 스크립트의 어느 산출물에서 왔는지** 추적 가능해야 한다.
- 그림·표 캡션이 실제 데이터와 일치하는지 확인. 데이터 없이 "예시" 그림을 만들지 않는다.
- 이상치·오타 의심 값은 고치지 말고 정제 규칙을 스크립트에 명시하고 위키에 기록한 뒤 사용자에게 묻는다.

### 논지·주장
- 저자의 핵심 주장·기여·결론을 조용히 바꾸지 않는다. 변경은 제안 후 승인.
- 강도를 임의로 높이지 않는다("~할 수 있다"→"~한다", "시사한다"→"증명한다" 금지). 관찰 자료의 상관을 인과로 쓰지 않는다.
- **데이터가 뒷받침하는 수준을 넘어서지 않는다.** PAPER_SPEC "주장 강도"가 상한선.

### 표절·저작권
- 출처 문장을 그대로 옮기지 않는다. 직접 인용은 따옴표+페이지. 타 논문 그림·표를 허가·출처 없이 복제하지 않는다.

### 참조 자료 보존 (2026-09-29 사용자 지시 — 교훈에서 나온 규칙)
- 세션 중 읽은 외부 자료(투고규정·작성요령·심사평·서식 템플릿·발표 요강)는 **반드시 저장소 안에 복사**한다. 바탕화면·임시 폴더에만 두면 다음 세션·다른 기기에서 재확인 불가.
- 위치 `docs/journal-guidelines/`, 파일명 `<저널약어>_<문서종류>_<개정연월>.<확장자>`. 바이너리(PDF·HWP)는 **텍스트 추출본(.md)을 같은 폴더에 동봉**.
- 그 자료로 서식·규칙을 적용했다면 스크립트 주석이나 STYLE_GUIDE에 **조항 번호와 파일 경로**를 적는다. "읽었다" 기록만 남기고 파일을 안 남기는 것은 위반.

### 외부 행위
- 원고·초록·데이터를 투고 시스템·이메일·외부 서비스로 전송·제출하지 않는다(사용자가 직접). 다운로드·업로드는 승인 후.
- 보호 파일(`main.md`·`references.bib`·`data/`·`figures/src/`·`PAPER_SPEC`·`OUTLINE`·`submitted/`·`deliverable/`)은 승인 없이 편집·삭제·덮어쓰기 금지. 대량 치환·재배열 전에는 백업.

### 불확실할 때의 기본 동작
- 인용 불확실 → `[CITATION NEEDED: ...]` · 수치 없음 → `[VALUE NEEDED]` · 논지 변경 필요 → 제안만 하고 대기 · 원자료 값 의심 → 기록 후 질문.

## 2. 작업 리듬과 완료 조건

- **브리스크하게.** 편집은 절/파일 단위로 묶는다. "한 문장마다 멈춰 검증"하지 않는다. 중간 보고 최소, 끝에 한 번 통합 보고.
- **단, 무결성 규칙은 속도와 무관하게 매 순간.** "일단 채우고 나중에 검증" 금지.
- **검증은 마일스톤·커밋 직전**: ① 인용 무결성(본문 키 ↔ bib) ② 자리표시자 0건(`[CITATION NEEDED]`·`[VALUE NEEDED]`·TODO·???) ③ 분량(타깃 제한) ④ 빌드 통과 ⑤ `check_style_rules.py` 0건. **완료 선언 전 전부 통과.**
- **수정 절차(EDIT_CHECKLIST §5)**: ① 체크리스트 확인 → ② 수정(문면은 반드시 **현재 파일에서 재추출** — 사용자가 Word/HWP에서 수시로 직접 고치므로) → ③ 검산 0건 → ④ **diff 0 확인 후** 커밋(선커밋 금지) → ⑤ 수정 이유(규칙)를 결정 로그에 즉시 기록(같은 자리를 반대 방향으로 다시 고치는 일 방지).
- **세션 종료**: 인계 노트 갱신 + 저널 노트 + `main`에 병합·푸시(기기는 `main`만 본다). pull 시 GitHub 버전이 정답(미커밋 수정 폐기 — 사용자 확정 2026-09-29).
- **기각된 안은 재제안하지 않는다.** 인계 노트 "기각안(재제안 금지)" 목록에 적는다. 번복은 사용자 승인으로만.

### 보고 형식 (논문 작업 후, 한국어)
```
- 수정한 파일:
- 생성한 파일/폴더:
- 추가/변경한 인용: (키, 출처 확인 여부)
- 삽입한 자리표시자: (위치)
- 논지·주장 변경 여부: (있으면 무엇을, 왜)
- 데이터·수치 변경 여부: (정제 규칙 추가 포함)
- 실행한 검증 명령 / 결과: (인용 무결성 / 자리표시자 / 분량 / 빌드 / 검산)
```

## 3. 집필 순서 (토대 → 초고 → 개고 → 투고)

1. **PAPER_SPEC 확정** — 제목(가제)·RQ·기여(한 문장씩)·방법·데이터·주장 강도·범위 밖·확정 대기 목록. 확정 전에는 본문을 쓰지 않는다. gap은 선행연구 조사 전에 단정하지 않는다.
2. **OUTLINE 확정** — 4절(서론 / 자료 및 방법 / 결과 / 요약 및 결론; 선행연구는 서론에 융합). 절마다 "주장할 한 문장". 그림·표 후보와 원천 파일.
3. **STYLE_GUIDE** — 용어 정본(동의어 통일 표), 단위, 표·그림 규칙, 문체 대원칙. 저널 확정 전엔 저널 중립.
4. **문헌 조사** — 축별로 등록(bib 0→N), 전 항목 Crossref/KCI/출판사 페이지로 서지 검증, 다운로드 없음. 문헌 노트 `status: unread` 유지 → 원문 읽은 뒤 `read`로 전환하고 수치 인용 격상.
5. **리스크 감사**(§6) — 집필 전에 한 번. 각 항목을 "해소" 또는 "한계로 명시" 중 하나로.
6. **스캐폴드** — `main.md`에 절 제목 + 절별 소스 노트·금지 표현 주석. 빌드 통과 확인.
7. **초고 권장 순서: §2 방법(정본 노트가 소스라 가장 기계적) → §3 결과 → §1 서론 → §4 결론.** 분량 제한 주시.
8. **사용자 초안 검토 → 수정방향 확정 → 전면 개고** — 문체 규칙(§4)을 적용하되 **수치·인용·주장 강도 불변**(재작성 후 인용 무결성 재검).
9. **오탈자 루프** — 사용자가 HWP/Word로 조립한 원고를 PDF로 보내면: 텍스트 추출 → 구판과 공백 제거 문자 diff → 변경부만 정독 + 금지 사전 스캔 + 표 참조·차례·수치 교차 검증 → **페이지 번호 + 전/후 완문**으로 보고.
10. **역동기** — 사용자가 정본 밖(HWP·Word·PPT)에서 고친 것은 정본(`main.md`·생성 스크립트)에 되돌려 넣는다. 파일 없이 정본을 먼저 고치지 않는다.
11. **투고판 생성** — 정본 무수정, 기계 치환(장 번호·교차참조·Table/Fig.·볼드 제거)으로 생성 파일을 만들고, 빌드 스크립트 머리 주석에 **조항 매핑**을 적는다. 쪽수는 실측(Word 통계).
12. **축약판**(분량·게재료 때문에 필요할 때) — §13의 절차와 원칙을 따른다. 전체본/축약판이 병존하면 수치·인용·주장은 동일해야 하고, 전체본을 고치면 축약판도 함께.

## 4. 문체·표기 규칙 (사용자가 수차례 재지적 끝에 확정한 것 — 전부 적용)

### 4.1 대원칙 11 (STYLE_GUIDE, 2026-07-25~27 확정)
1. **간결** — 한 내용 한 문장. 근거·부연은 수치와 결론만. 방법론 방어 논리를 문면에 길게 깔지 않는다. "A가 아니라 B" 대조 구문 남용 금지(앞 문장이 부정·한계를 말했으면 다음은 긍정만).
2. **누구나 쉽게** — 전문어는 첫 등장에서 짧게 풀거나 `한글(English)` 1회 병기. 꼬리표 나열 대신 실체를 일상어로.
3. **능동태 우선** — "~되어진다"·"~로 여겨진다" 금지. 행위 주체를 주어로.
4. **직역투 배제** — 줄표 삽입구, 명사 나열, "~함을 확인한다"식 명사화 금지(§4.4 목록).
5. **명확한 주어·술어** — 긴 수식·사슬 구문을 줄여 주어와 술어가 바로 만나게.
6. **표준 학술 용어** — 국내 정착어(강건성, 측정 오차, 최적정지 …). 임의 조어·음차 금지. 새 용어는 **KCI 용례 검색**으로 정착 여부 판정.
7. **구어 표현 자제** — "모아 쓴다"·"출렁여"·"걷어내"·"통째로" 류 배제. 쉬운 말 ≠ 헐한 말.
8. **통계 서술 한 줄 원칙** — 결과 문장은 직관 단위(%·원·kg)로 한 줄에 완결. 수치 뒤에 "~하며, ~는 뜻이다"로 풀이를 잇대지 않는다(풀이가 필요하면 수치를 풀이 안에 녹인다: "약 51%(0.41 로그포인트) 상승한다"). 표에 있는 세부 수치는 본문에서 반복하지 않는다.
9. **설계 논리 선행, 추정 방식 후행** — 방법 절은 "무엇을 재고 근거가 어디서 오는가"를 앞에, "어떻게 추정하는가"를 뒤에. 핵심 설계 결정을 "한편/다만"으로 끝에 붙이지 않는다. 단 결과 절의 "관측→해석", "결과→유보·한계" 순서는 관례이므로 유지.
10. **주장 선행, 근거 후행** — 해석·유보·강건성·정책 함의 문단은 명제를 먼저, 근거를 "~기 때문이다"로 뒤에. 근거 나열 끝에 "요컨대/즉 ~이다"로 주장이 꼬리로 붙는 형태 금지.
11. **예고와 내용 일치** — "후속 과제는 두 가지이다"라고 했으면 그 성격의 항목만. 정책 함의는 연구 과제 목록에 끼우지 말고 별도 대목. 항목 뒤 관련성 꼬리 문장("이는 ~와 직결된다") 금지.
- ⚠ 공통 단서: 문체 손질이 수치·인용·주장 강도를 바꾸면 안 된다.

### 4.2 괄호 (2026-07-26 확정)
- **허용**: 내주 인용, 영문·한자 병기(첫 등장), 절·표·그림·식 참조, 기간·주차, 단위 환산쌍.
- **금지(전부 서술로)**: 통계 보고값 `(β=−0.316)`·`(R²=0.50)`, 값+출처, 용어 명명, 파라미터 스펙, 문장급 설명, 나열. 통계 괄호는 **표·표 주석 안에서만**.
- 괄호 겹침(이중·삼중) 절대 금지.

### 4.3 기타 확정 규칙
- **동격·요약의 "즉" 금지** — "A, 즉 B"는 정의를 별도 문장으로 분리하거나 관형절로 녹인다. 문두 "즉 ~이다" 재진술은 즉 없이 평서문, 중복이면 삭제.
- **"증거" 전면 폐기** — "~라는 증거는 없다"→"~라고 볼 근거는 없다"·"~로 보기 어렵다"·"~라고 결론지을 수 없다".
- **"유보가 필요하다/중요한 유보는"** → "~에 주의해야 한다"/"~에는 중요한 한계가 있다". **"벤치마크"**→"~모형의 예측". **"크기를 주장하지 않는다"**→"크기는 신뢰하기 어렵다".
- **접속어는 논리 관계와 일치** — 반대 방향 유보에는 "다만"(나열의 "아울러" 금지), 유보를 딛고 가는 결론에는 "그렇더라도"(유보 직후 "요컨대" 금지).
- **문단 완결 구조** — 한계·유보 문단은 "왜 중요한가 → 증거 → 그래서 어떻게 되는가". 맺음은 새 정보여야 하고, 다른 절이 말할 내용의 예고성 중복("~는 3.3절에서 논의한다") 금지.
- **검토 대화 잔재 본문 금지** — 대상 없는 경고문, 본문 미정의 내부 개념, 예고성 중복. 방어 논리의 보관처는 표·표 주·디펜스 노트·리스크 감사.
- **긁어 부스럼 금지·AI투 제거(2026-10-03~06)** — 주석·본문의 계산 과정·자료 사정·점검 보고·내부 근거 언급, 예고 문장, 되풀이 요약, 라벨 문장, 'A가 아니라 B' 남용은 쓰지 않는다. 유형표와 판정 질문은 §14.
- **라벨 문장 금지** — "첫째는 가치이다" 대신 서수를 실체 문장에 바로 붙인다.
- **겹말 금지** — 국내외 모두, 뒤 이후로도, 대부분~뿐, 주평균~평균, 추정하는~추정되는.
- **종결어미 '이다' 통일** — 가치이다·형태이다·단위이다(모음 끝 명사+"다" 금지). 과거형 "측정했다·적용했다·확인했다"는 현재형으로.
- **전문 단위는 첫 사용에서 직관 단위로 환산** — "약 51%(0.41 로그포인트)" 형태. 단위 강의 문장은 넣지 않는다.
- **의인화 금지** — "프리미엄은 ~를 주장하지 않는다", "모형은 ~하라고 한다" → 행위 주어를 사람/연구로.
- **시사점은 실증 수위까지** — 메커니즘 서술은 가능, 방향 처방("그 몫을 농가로 옮길 수단")은 가치판단이라 금지.

### 4.4 직역투 탐지·수정 순서 (2026-07-27 확정)
- **탐지 단서**: 공간 은유(~아래의, ~위에서, ~공간, 달력), 명사 사슬·명명(식별의 원천, 해석의 경계/범위, 간명한 사양, 집계적, "~에 대한 검정이 된다", 독립 관측, 보조 관찰, 무게중심, 변이), 어미·조사(~에서의, ~으로의, ~됨을 보여준다, 시사적이다), "~를 보고한다", "공백으로 남아 있다", "차별성을 가진다", "~의 그것", "통해 도출"(사례별 판단), "가치·정보·행동 세 측면"(꼬리표 나열).
- **판정**: KCI 용례로 국문 정착 여부 확인.
- **수정 순서**: ① **삭제**(문맥이 뜻을 담당하면 단어만 뺌: "평균 격차의 변이는"→"평균 격차는") → ② **서술 해체**(명사구를 술어로: "독립 관측이기도 하다"→"비용 파라미터에 전혀 의존하지 않는다") → ③ **정착어 대체**("보조 관찰"→"방증"). "X 증거" 명사 결합은 해체, 술어형은 유지였다가 **전면 폐기**로 격상됨.
- 쉬운 말이 필요할 때는 **원고 본문의 동사를 먼저 찾는다** — 새로 지은 문장이 직역투 재유입 경로가 된다.

### 4.5 표 작성 규칙 8 (2026-07-28 확정)
1. 열 구조는 **"무엇을 / 어떻게 / 결과"**로 분리. 라벨 괄호에 설정을 욱여넣지 말고 설정값 열로. 첫 열 머리를 비우지 않는다.
2. 행 이름은 **일반화된 명사**("입고 시점"→"저장 시작 시점"). "기준" 단독 금지 → "기준 모형(변경 없음)".
3. 개별 값 나열 금지 — 같은 파라미터의 연속 구간은 `~`, 성격이 다른 설정은 `/`. 둘을 섞지 않는다(연속 구간으로 오독).
4. 각 행에 **기준값 병기** — "φ=0.983 (기준 0.885)".
5. 대안 결과가 여럿이면 **보수적인 하나만 게재**, 나머지는 주에.
6. **표 주는 개조식** — 값·비교 기준만. 산출 과정은 위키·디펜스 노트로. 단 오독을 부르는 비교 기준은 반드시 남긴다. 주 번호별·출처는 각각 다른 줄.
7. 표에 있는 세부 수치는 본문에서 반복하지 않는다.
8. **캡션은 개조식 명사구** — 문장형 발견 서술 금지(발견은 본문 몫). 괄호는 (단위·기간)만.
- 기초통계량 표: 평균·중앙값·최대·최소·표준편차·왜도·첨도. 유의수준 `*, **, ***는 각각 10%, 5%, 1%에서 유의`. 병합 셀 최소화(HWP 변환 대비).

### 4.6 금지 패턴 사전 (검산 스크립트 `check_style_rules.py`에 등록)

## 6. 리스크 감사 — "억지가 없는가" (wiki/risk-audit.md 패턴)

- 계기가 된 프롬프트: **"지금까지 작업들은 논리적으로 허점이 없고 억지가 없어?"**
- 성격: 계산·데이터가 아니라 **"그 숫자로 무엇을 주장하는가"의 층**. 심사자 반박 시나리오를 미리 적는다.
- 항목 형식(R-1 … R-n, 🔴🟠🟡 등급):
  ```
  ## 🔴 R-k. <한 줄 제목>
  - 문제:
  - 반박 시나리오: "<심사자가 할 말 한 줄>"
  - 현재 상태: 미해소 / 부분 / 해소
  - ✅ 쓸 문장 상한: "…"
  - ❌ 쓰면 안 되는 문장: "…"
  - 해소 방향:
  ```
- 하단에 **실행 목록 표**(할 일 · 해소 대상 · 상태) + **"반대로, 튼튼한 부분(과소평가 금지)"** 절.
- 사용법: 집필 전·투고 전 재독. 각 항목이 **해소되었는지 / 한계로 명시되었는지** 확인. 둘 중 하나도 아닌 채 본문 주장이 나가면 그때가 억지.
- 전형적 위험 유형: 프레임과 결과의 불일치(측정 가능한 것은 프레임이 아니고, 프레임인 것은 측정 불가) / "이상현상"이라 부른 것이 표준 이론의 예측 / 귀무가설 설정이 헐거움(미포함 비용) / 파라미터 개념 불일치 / 사후값을 사전 기대값처럼 서술 / 정량 근거 없는 수식어("소수") / 사후 가설(post hoc)을 사전 예측처럼 서술.
- 에이전트가 정할 사항이 아닌 것(프레임 선택)은 **결과를 본 뒤 사용자가 결정**.

## 13. 축약판 만들기 — 2026-10-02 KJOA 축약판(28쪽 → 14쪽)에서 고려한 사항

### 13.1 계기와 판단 틀
- 계기는 분량 상한이 아니라 **게재료**였다(사회과학 기본 13쪽, 초과 1쪽당 20,000원). "13쪽은 상한이 아니므로 축약 불필요, 비용 판단만"이 먼저 확정됐고, 사용자 지시는 **"이 본은 저장해 두고 13쪽 내외 축약판"** — 즉 축약은 전체본의 대체가 아니라 **예비안**이다.
- 비용 계산은 **기준 단위가 불명(인쇄 쪽 vs 원고 쪽)**이라 두 시나리오를 표로 병기했다. 인쇄 쪽수는 같은 저널 최근 게재 논문의 글자 수 비례(쪽당 약 1,630자)로 추정하고, 추정임을 명시하고 학회 문의로 확정하기로 했다. 전해 들은 기준(인쇄 쪽)은 "서면 확인 아님"을 적어 두었다.
- 사용자 성향: **"예산상 무리 없으면 축약하지 않는 쪽"** → 전체본 투고가 기본 방향, 축약판은 확정 전까지 유지. 비용 차이(약 8만~10만 원)를 수치로 보여 주고 결정은 사용자에게.
- 참고 자료(투고료·게재료 안내, 게재 논문 8편의 양식 정리)는 전부 `docs/journal-guidelines/`에 원문+적용 계산으로 저장했다(참조 자료 보존 규칙).

### 13.3 축약판 원고의 성격
- 축약판은 **생성 파일이 아니라 직접 쓰는 원고**(`main_kjoa_short.md`). 기계 치환으로는 분량이 줄지 않기 때문이다.

### 14.1 "긁어 부스럼 금지" — 주석·본문에 굳이 밝힐 필요 없는 것 (10-03 사용자 지시)

### 14.2 "AI가 쓴 느낌"이 나는 문장 유형 — 본문판 (10-03 번호표 22건, 10-06 12건 적용)
사용자가 원고 전체에 대해 느낀 문제. 에이전트가 원고를 훑어 유형별로 번호표를 만들고 사용자가 번호로 적용·제외를 지시했다.

| 유형 | 모양 | 처리 |
|---|---|---|
| **예고 문장** | "…는 3.2절에서 확인한다", "두 가지 한계가 있다. 첫째, … 둘째, …", "주4~8로 바꾼 경우도 확인한다", 절 첫머리의 당연한 도입문("~에는 ~ 모형이 필요하다") | 삭제. 결과·단서는 해당 절에 그대로 있으므로 예고만 뺀다. 서수 틀(첫째·둘째)도 함께 |
| **되풀이 요약** | "따라서 …의 혼합이다", 문단 끝에 앞 문장을 다시 정리하는 문장, 다른 절(결론)에 같은 문장이 있는 것 | 삭제. 결론 문장은 결론 장 한 곳에만 |
| **가르치듯 한 풀이·라벨 문장** | "하나는 연도 효과이다. 다른 하나는 계절 효과이다", "이 잔차는 … 편차이다", "φ는 … 값이다" | 라벨 문장 삭제, 풀이는 수식어로 녹임 |
| **'A가 아니라 B' 대구** | "계절이나 시장 전반의 특성이 아니라 … 국한된 현상이다" (원고에 6회) | 뒤 문장이 같은 내용을 보여 주면 "A가 아니라"를 뺀다. **핵심 결론 문장(초록·§4)의 것은 남긴다** |
| **묻지 않은 것에 미리 답하기** | 계산 과정("창고료 평당 11~14만 원을 환산하면"), 점검 보고("전 시나리오에서 V_C ≥ V_B 성립, MC 표준오차 9원"), 내부 근거 언급("비용 조사 원문과 일치") | 삭제. 독자가 볼 수 없는 내부 자료 언급은 특히 금지. 심사에서 물으면 답변으로 |
| **양보 구문** | "검증할 수는 없다. 대신 … 검증한다" | 한 문장으로("~자료가 없으므로 ~로 검증한다") |
| **연결 수사** | "네 결과는 하나의 결론으로 모인다", 평가 부사("일찍이", "정밀하게"), 꼬리 문장("…이론도 있다") | 삭제·병합 |
| **단서 + 즉시 방어 틀** | 단서를 말한 뒤 곧바로 "다만 …"으로 방어 (주의사항 네 가지에서 반복) | **유지 권장** — 틀은 기계적이지만 내용이 주장 범위를 한정하고 토론 대응이므로 |

- **구분 4단계로 제시**: 빼도 됨(군더더기, 빼도 주장·수치 그대로) / 단서 — 내용은 남김(틀·중복만 걷어냄) / 오늘 유지하신 대목(앞서 유지 결정한 문단을 다른 관점에서 다시 올림) / 유지 권장. 사용자는 "빼도 됨" 대부분을 적용하고, 7월 확정형 문단(부트스트랩 설명, φ 문단, 시장지배력 단서, 한계 문단)은 제외했다.
- ⚠ 이 작업은 **7월 확정 결정 일부를 번복**했다(예: "유지되어 결과에 영향을 주지 않는다"→"유지된다", "네 결과는 하나의 결론으로 모인다" 삭제). 번복은 사용자가 번호로 지시했을 때만, 그리고 EDIT_CHECKLIST §6에 "번복된 이전 확정"으로 명시.

- 사용자가 지킨 것: 핵심 표(기초통계·파라미터·강건성)와 그림 1·2, 손익분기 대조, 후속 과제 3건은 **유지**. 축소는 사용자 선택이지 에이전트 판단이 아니다.
- 적용 후 검증: 수정안 문장의 수치를 정본과 기계 대조(새 수치 0), 인용 키 검산, 글자 수 추이(24,591 → 20,090 → 19,060자), 쪽수는 Windows에서 실측(맥북은 불가 — 미리보기 PDF가 옛 빌드임을 기록).
- 보존: 줄이기 직전 상태를 **태그 + docx 사본**으로(`kjoa-full-28p-newtitle`). **판 이름 확정**: 제출본(줄인 판, 정본에서 빌드) / 전체본(안 줄인 판, 태그·사본) / 축약판(§13의 별도 원고). 앞으로 이 이름으로만 부른다.

### 14.4 지시 해석의 교훈 (10-03 같은 날 정정)
- 사용자가 번호로 제외를 지시한 항목을 에이전트가 "덱 그림 확인 대상"으로 잘못 읽어 '결정 대기'로 기록했다가 정정. **규칙: 번호 지시는 적용/제외 명단을 그대로 받아 적고 해석을 보태지 않는다. 확인 대상이 하나(36번)면 하나만.** 정정 사실은 EDIT_CHECKLIST·인계 노트에 ⚠로 남긴다.
- 대체안(발표 덱 그림 변경판)을 보고할 때는 **원고에 없는 수치**("만기 잔량 16%")가 섞이는지, 본문 문장과 어긋나 보이는지를 함께 보고한다. 사용자는 대체 대신 삭제를 택했다.

### 14.5 제출본 조판 다듬기 체크리스트 (10-03, 사용자 지적에서 나온 것)
- **수식 그림 글꼴**: matplotlib 기본(DejaVu Sans)은 본문 Times 계열과 어긋나 "뭉툭"하다 → STIX/Times 계열, 600dpi, 본문 12pt·표 10pt와 같은 크기로 재생성. 수식 내용은 정본과 동일.
- **수식 기호 표기 통일**: 그리스 소문자·변수(β φ δ σ ε λ c)는 기울임, 대문자(Δ Π)는 곧은 글씨, 첨자 속 글자는 기울임·숫자는 곧은 글씨, 2단 첨자(t₀), c·h는 얇은 공백. 그림 안 기호도 같은 규칙으로 다시 그린다(수치 동일 확인). 원고 md 문면은 바꾸지 않고 **빌드 단계에서** 적용.
- **양쪽 정렬의 큰 낱말 간격**: Word가 한글을 어절 단위로만 줄바꿈 → 공백 없는 긴 덩어리(괄호·가운뎃점·내주 포함 20자 이상)가 밀리며 앞줄이 벌어짐. 빌드 단계에서 한글 뒤 여는 괄호 앞·가운뎃점 뒤·내주 앞에 폭 없는 공백(U+200B)을 넣어 줄바꿈 자리를 만든다(표·영문·References 제외). "한글 단어 잘림 허용"은 영어 단어까지 자르므로 쓰지 않는다. HWP에서 이상하면 끈다.
- **표 주석**: 주 번호별·출처를 각각 다른 줄. 그림 출처 줄은 게재본 관행을 먼저 확인(없으면 넣지 않는다).
- 렌더 확인은 Windows + Word/한글에서만 가능 — 맥북 세션은 "사용자 확인 대기"로 넘긴다.
- **검토용 표시본**: 수정안 위치를 바로 보게 제출본과 같은 내용에 형광펜(노랑=빼도 됨, 초록=단서 남김, 회색=유지)과 빨간 【번호】를 넣은 docx를 따로 만든다. 제출용이 아니며, 적용 뒤 삭제.
